# Cloudflare Worker Migration Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Serve wardzinski.info and www.wardzinski.info from a Cloudflare Worker with Static Assets, deployed by GitHub Actions on push to `master`, and retire the homelab Kubernetes deployment.

**Architecture:** An assets-only Worker (no `main`, no script) whose `wrangler.jsonc` points at `app/` and declares two custom domains. GitHub Actions runs `wrangler deploy` on push to `master` and `wrangler deploy --dry-run` on pull requests. DNS cutover is done through the Cloudflare API after the first deploy, ordered so the old site keeps serving until the last step.

**Tech Stack:** Cloudflare Workers Static Assets, wrangler 4.130.0, Node 22, GitHub Actions (`actions/checkout@v7`, `actions/setup-node@v7`, `cloudflare/wrangler-action@v4`), `gh` CLI, Cloudflare REST API.

**Spec:** `docs/superpowers/specs/2026-09-09-cloudflare-worker-migration-design.md`

### Task 3: GitHub Actions deploy workflow

**Files:**
- Create: `.github/workflows/deploy.yml`
- Delete: `.github/workflows/build-and-push.yml`

**Interfaces:**
- Consumes: `package-lock.json` (Task 1) for `npm ci`; `wrangler.jsonc` (Task 2).
- Produces: workflow named `Deploy to Cloudflare Workers`, job id `deploy`, used by Task 6 (`gh pr checks`) and Task 7 (`gh run watch`). Reads repo secrets `CLOUDFLARE_API_TOKEN` and `CLOUDFLARE_ACCOUNT_ID`, set in Task 6.

- [ ] **Step 1: Write the workflow**

```yaml
name: Deploy to Cloudflare Workers

on:
  push:
    branches: [master]
  pull_request:
    branches: [master]
  workflow_dispatch:

jobs:
  deploy:
    runs-on: ubuntu-latest
    permissions:
      contents: read
    steps:
      - uses: actions/checkout@v7

      - uses: actions/setup-node@v7
        with:
          node-version: 22
          cache: npm

      - run: npm ci

      - name: Validate config (pull request)
        if: github.event_name == 'pull_request'
        uses: cloudflare/wrangler-action@v4
        with:
          apiToken: ${{ secrets.CLOUDFLARE_API_TOKEN }}
          accountId: ${{ secrets.CLOUDFLARE_ACCOUNT_ID }}
          command: deploy --dry-run

      - name: Deploy
        if: github.event_name != 'pull_request'
        uses: cloudflare/wrangler-action@v4
        with:
          apiToken: ${{ secrets.CLOUDFLARE_API_TOKEN }}
          accountId: ${{ secrets.CLOUDFLARE_ACCOUNT_ID }}
          command: deploy
```

Note: `wrangler-action` uses the wrangler already installed by `npm ci`, so the version stays pinned to `package.json`.

- [ ] **Step 2: Edit the redirect rule**

Run with the Cloudflare execute tool:

```javascript
async () => {
  const zone_id = "410d16e3cc13ee121e99146cc7528322";
  const ruleset_id = "238e293ba6834bca80f6993692442664";
  const rule_id = "5a489bdc90f648819d9f49946474b059";
  const r = await cloudflare.request({
    method: "PATCH",
    path: `/zones/${zone_id}/rulesets/${ruleset_id}/rules/${rule_id}`,
    body: {
      description: "Redirect resume.wardzinski.info to wardzinski.info",
      expression: '(http.host eq "resume.wardzinski.info")',
      action: "redirect",
      action_parameters: {
        from_value: {
          status_code: 301,
          preserve_query_string: true,
          target_url: { value: "https://wardzinski.info" }
        }
      },
      enabled: true
    }
  });
  return { success: r.success, errors: r.errors,
           rules: (r.result?.rules || []).map(x => ({ expression: x.expression, target: x.action_parameters?.from_value?.target_url?.value })) };
}
```

Expected: `success: true`, one rule with the new expression and target.
